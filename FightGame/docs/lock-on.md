# 敵ロックオン（仕様メモ）

非ロックオン時に一定距離内へ入った敵を自動で捕捉し、プレイヤーがその方向を向き続ける機能。実行時の真実はソース。数値は仮で、実装時に調整する。

関連: [game-overview.md](game-overview.md) / [ai-behavior.md](ai-behavior.md) / [implementation-tasks.md](implementation-tasks.md)

---

## 狙い

- 向きを合わせる操作コストを外し、**距離の選択**に注意を集める。コアの「有利間合いの探索と維持」を濃くする
- 後退しても敵へ攻撃を出せるため、プレイヤーが躊躇なく下がれる。間合いを測る後退が選択肢として成立する
- ロックオンボタンは持たない。捕捉と解除は距離で自動、対象の切替だけ手動

## 数値の前提

現在の攻撃データ（ProtoWorld）:

| 攻撃 | 射程 | 扇の角度 |
| --- | --- | --- |
| プレイヤー近距離 | 1.7 | 160° |
| プレイヤー遠距離 | 6.2 | 60° |
| 敵の最長 | 4.2 | 30° |

- 距離 **4.2〜6.2** が「敵の攻撃圏外から遠距離攻撃を当てられる帯」。ロックオンで守りたいのはこの帯
- 遠距離攻撃の扇は 60°（半角 30°）しかない。向きがズレると当たらないため、この帯でロックオンが切れてはいけない

### 必須制約

- **解除半径 > プレイヤー遠距離攻撃の射程（現在 6.2）**。射程内で解除されると狙いが崩れる
- **捕捉半径 < 解除半径**（ヒステリシス）。同値だと境界で捕捉と解除が毎フレーム入れ替わる
- 出発点の目安は捕捉 6.5〜7.0 / 解除 7.5〜8.0

## 操作

| 操作 | 割り当て |
| --- | --- |
| 捕捉 | 自動（入力なし） |
| 解除 | 自動（解除半径の外に出る、対象の死亡・消滅） |
| 対象切替 | Q / E（段階1）、右スティック左右（段階2） |

- 右スティック左右は現在カメラ yaw の唯一の操作手段。カメラ自動追従が入るまで切替に奪えない
- E は ProtoWorld で `"TheWorld"`（時止め、System 未配線）として登録済み。使うなら登録名を整理する
- 入力は「切替方向（左 / なし / 右）」へ一度解決してから使う。段階2の追加を分岐1つで済ませるため
- スティックは押し続けで連続切替になるため、前フレームの閾値超えをラッチして1回だけ効かせる。Input 側に離し検出の公開 API はないので、ラッチは Component 側に持つ

## 状態の持ち方

- `LockOnSearch`: 探す側に常設。捕捉半径・解除半径・切替入力のラッチ
- `LockOnAction`: **ロックオン中だけ付く**。対象 Entity を持つ。既存の `GuardAction` / `AttackAction` と同じ「Component が存在する間その状態」の流儀

命名は `Lookon` ではなく `LockOn` とする。既存に `LookComponent` / `LookMove` / `LookLaserPoint` があり、`Look`（注視）との区別が付かなくなるため。

### 遷移

非ロックオン時（`LockOnSearch` あり・`LockOnAction` なし）:

1. 敵を列挙し、死亡している敵を除外する
2. 捕捉半径以内、かつカメラ画角内に絞る
3. 該当のうち**最も近い**敵を選ぶ
4. `LockOnAction` を付ける

ロックオン中（`LockOnAction` あり）:

1. 対象が有効かつ生存しているかを見る。NG なら解除
2. 切替入力なし: 解除半径の外に出たら解除
3. 切替入力あり: 入力方向側の敵のうち、現在の対象から角度が最も近いものへ切替。候補は解除半径内に限る。該当がなければ維持

- 「最初に見つかった敵」で決めない。列挙順は内部の配列順で、Entity の削除のたびに入れ替わる
- 倒した敵は Entity がしばらく残る（死亡フラグのあと遅延削除）。死亡チェックがないと死体を向き続ける

## 向きの制御

- ロックオン中の向きは **yaw のみ**扱う。対象方向の目標角度へ、回転速度の上限を掛けながら差分で寄せる（既存の移動方向へ向く処理と同じ寄せ方）
- 移動方向へ向く既存処理とは**排他**にする。同じ回転差分に別方向を積むと打ち消し合う
- 攻撃モーション中は振り向かせない（移動許可フラグに合わせる）。振り向き攻撃で理不尽にならないようにする

### 既存の注視処理（`LookComponent` / `LookSystem`）を流用しない理由

- pitch を必ず書くため、敵の高さに向かってプレイヤーが前傾・後傾する。yaw だけに限る手段がない
- プレイヤーは移動由来の yaw が回転の蓄積側に載っている。そこへ絶対角度を書くと二重に足される

どちらも敵（レール系）の注視では問題にならないが、プレイヤーは前提が違う。

## System の分け方

- 対象決定（捕捉・解除・切替）と、向きの適用は別 System にする
- 対象決定は入力の解決前に置く。向きの適用は Pose 合成後、移動方向へ向く処理と同じ位置に置く（現在角度を Pose から読むため）
- ファイルは `LockOnSystem` の `.h` / `.cpp` ペアに置く

## 段階

| 段階 | 内容 | 目的 |
| --- | --- | --- |
| 1 | 捕捉・解除・切替（Q / E）・向きの固定 | 距離のヒステリシスと向き固定の検証。カメラは手動のまま |
| 2 | カメラの自動追従、右スティック左右での切替 | 移動入力はカメラ基準なので、**狙いの本体はここ** |
| 3 | 対象マーカーの表示 | 誰を狙っているかを見せる。切替が実用になるのはここから |

段階2が本体である理由: 移動入力はカメラの yaw でワールド方向へ変換される。カメラが敵を向いていないと、プレイヤーの向きだけ固定しても「下がる」入力が敵から離れる方向にならない。

段階3の前提: ワールド座標からスクリーン座標への変換が未実装。マーカーはこの工事が先。

## 未対応・後回し

- 明示的な解除操作。今は距離を離す以外に外す手段がない。複数敵で間合いを組み替えるときに困るなら追加を検討する
- 壁越し・遮蔽の考慮。距離と画角だけで捕捉するため、障害物の裏の敵も対象になりうる
- 敵側からのロックオン利用。仕組みは共通化できるが、今回はプレイヤーのみ
