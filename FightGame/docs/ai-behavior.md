# 敵AIの振る舞い（設計メモ）

間合い格闘における敵AIの意図整理。実行時の真実はソース。数値は仮で、実装時に調整する。

関連: [game-overview.md](game-overview.md) / [implementation-tasks.md](implementation-tasks.md)

## 狙う体験

- 大前提: **無策で攻撃を当てにいくと、被弾しやすく不利なトレードオフになる**。  
  工夫により、低リスク高リターンの交換を作れることを遊びの核にする。
- 距離によって「自分と相手の選択肢」が変わるため、**どの位置に立てば相手に不利な選択肢を選ばせられるか**を考えて戦うのが楽しい状態を目指す。

- **敵**: 性質を踏まえ、**位置関係の目標**を持ち、その下で有利な攻撃・移動手段を選ぶ。技が当たりにくければ信頼を下げて混ぜる。
- **プレイヤー**: 「どの距離の攻撃を当てに来ているか」「敵は不利脱出／有利活用／様子見のどれか」を読み、立ち位置でテンポを取り、敵の目標達成を邪魔したり誘導したりする。
- **ガン逃げ禁止寄り**: 近距離が不利だからといってただ距離を取るだけにしない。隙を作るために近距離で戦し、チャンスが生まれたら離れる。
- **対抗アクション（ガード／ジャンプ）への大反応**: 初期は入れない。
- **プレイヤーが状況を握る手段（初期）**: 主に間合いとテンポ。専用の制御メカニクスは後段。

毎フレーム全部を賢くしない。**性質（ゆっくり）→ 目標（たまに）→ 手段（AI Tick）** に分ける。

### 最小工夫例

- プレイヤーはジャンプ／ガードで敵攻撃を受けられる。
- 敵は遠距離ではジャンプ・ガード両方に有効な手段を持つ。
- 敵は近距離ではジャンプにしか有効な手段を持たない。  
  そのためプレイヤーは、**近距離で戦う意図**を持つと有利を作りやすい。

### 基本攻略ルート

1. 有利な位置を探す
2. その位置を保つ
3. 位置関係を揺るがす行動を相手が行う
4. その行動に対処する
5. 完封する

### 低リスク高リターンの攻略ティア

#### ティアS

- 有利位置関係を揺るがす行動まで対策して戦う。
- 通常戦闘よりリスクが小さく、成立すれば圧勝しやすい。
- この状態を「上手く戦えている」基準とする。

#### ティアA（基準）

- 対策を持たなくても、有利位置への移動と相手の対策行動への対応を繰り返す。
- 大きなミスがなければ、ダメージレースでやや有利を取りやすい。
- いくつかある相手行動への対策を1つでも見つけられれば、勝率が大きく上がる想定にする。

#### ティアB

- 最低限、危ない位置を避けて殴り合う。
- 有利位置の維持は難しくても、相手の最得意位置を避けるのは難しすぎない設計にする。
- 初見はこの層で戦いながら、有利位置を探索する想定。

#### ティアC

- 相手の最得意間合いで殴り合う。
- 初見でも最低限避けたい層で、ここに入ると敵が過剰に強く感じやすい。
- 「工夫しなければ勝てない」を伝えるための下限として扱う。

### プレイングゴリ押しの扱い

- 有利間合いではないが、プレイング密度で押し切れる位置は存在しうる。
- ただしコンセプト逸脱のため許容範囲は制御し、上位ティア行動より期待値が低くなるようにする。

### ユーザーにさせる工夫ルール

- 全行動の自由化よりも、**一定量のアクション判断を必須化**する。
- 有利位置へ移動し、通常択は安全に捌く。
- 崩し行動に注意を割き、来たら対抗アクションで返り討ちにする。
- そのまま有利位置を維持して勝ち切る。  
  これを最も気持ちよい成功体験として設計する。

### 対抗アクション実装メモ（段階・変更前提）

コアを「有利間合いの探索と維持」にした以上、攻撃種×ガード／ジャンプの有効度マトリクスや、アクションごとの間合い得意不得意は **今の実装目標にしない**（複雑・動きの固定化）。近／遠の使い分けもコア維持よりメインにしない。

段階実装:

1. 耐久・回避手段としてだけ通す  
2. 成功時メリットで役割差（強化など。既存案と両立）  
3. 余裕があれば間合い要素を薄く織る  

「自分の間合いから取りたいリターンで位置を決める」は理想だが後段。

## データの置き場（責務）

| 置き場 | 責務 | 例 |
| --- | --- | --- |
| **BB** | Sense／モード更新が書く **入力**。技キットと Role（係数）は同じ袋 | 位置、技データ、Role 係数、canAttack |
| **AIMind** | **思考の状態と記憶**（可変） | 現在 stance、updatePoints、Evidence、stanceContinueCount |
| **AIContext** | 木の **進行度** | nodeIndexes、actionDuration |
| **AIResult** | 今 Tick の **出力** | MoveDir、AttackIndex、UseAttack |

```text
AIRuntime
  context … 木の進行
  mind    … 思考の状態と記憶（可変）
  result  … 今 Tick の出力

BB.enemyDatas[entity]
  position / flags / attackDatas / Role 係数
```

技キットが変わるときは Role 係数も同じ更新経路で書き換える（別構造体に分けない）。`AIRole` 専用型は置かない（BB への係数は Component `AIRole` から Sense 経由で書いてよい）。

### AIMind が持つもの

- 現在の `stance`
- `updatePoints`（次の Stance 再評価まで）
- Evidence / 記憶: `lastAttackIndex`、`sameAttackStreak`、被弾・成功（未配線）、**現行 Stance の `stanceContinueCount`**
- Stance 再評価後は Evidence をリセットまたは減衰してよい

### BB の Role（係数）が持つもの

- `distCoefficient` … 得意間合い用（`advantagePos` / `disadvantagePos`）
- `farnessCoefficient` … 様子見用の距離の遠さ（`farness`）
- `hitCoefficient` … `ScoreByHitCount`
- `stanceCoefficient` … `ScoreByStance`（`>1`）
- 技データと同じタイミングで書く。当面 Sense 未配線ならデフォルト値

## 三層（目標と手段を分離）

| 層 | 意味 | 変わる速さ |
| --- | --- | --- |
| **Role（性質）** | カーブ係数セット（BB） | 技キットと一緒。モード切替で変わりうる |
| **Stance（目標）** | しばらく追う位置関係の目標 | Evidence／更新ポイントが閾値を超えたとき |
| **Action（手段）** | 目標のための具体 | AI Tick（実行中はコミット可） |

流れ:

1. Role の係数が Stance スコア計算のカーブに入る  
2. Stance（目標）が Action の候補と重みを変える。**詰め／離しは Stance 名ではなく手段**  
3. Action の結果は `AIResult` へ  
4. 前隙・後隙・判定は攻撃データと System／BT 葉に任せる  

道具の置き場:

- **Utility**: Stance 付け直し、および Stance 内の Action 選択  
- **BT**: 実行の器  
- **GOAP**: 現要件では使わない

## Stance＝目標（3種に固定）

| Stance（目標） | 意味 | 手段の例 | プレイヤーに見える／干渉できること |
| --- | --- | --- | --- |
| **不利脱出** | 不利な位置から抜ける | 隙作り近接のあと離間、など | 追撃・カットで脱出を邪魔できる |
| **有利維持活用** | 有利な間合いを保ち得点 | 得意距離の微調整・得意技 | 間合いを崩す |
| **ニュートラル様子見** | 一方的にしない | 探り・待機・技切替 | プレイヤーがテンポを取れる |

旧「詰め／離し」は Action の手段ラベル。Stance 名には使わない。

### 有利／不利

- 距離と技データの得意 mid、および Role の `distCoefficient` で決める。
- 不利脱出中でも近接 Action を選びうる。ガン逃げだけにしない。

### ステート継続の掛け方

`ScoreByStance(stanceContinueCount, …)` は **いまの `mind.stance` のスコアにだけ**掛ける。3候補すべてに同じ係数を掛けると argmax で打ち消される。

```text
scoreProbe / scoreHold / scoreEscape を生で計算
mind.stance に対応するスコアだけ *= ScoreByStance(...)
→ argmax
```

- `stanceContinueCount` は現行 Stance の継続長さ（`sameAttackStreak` とは別）
- Stance が変わったら 0 に戻す
- 係数 `>1` の減衰は「長く続けすぎたら切り替えやすくする」方向

## Role（性質）＝カーブ係数

技データと同じく **BB の `BBEnemyData`** に置く（専用 `AIRole` 構造体は増やさない。ECS の `AIRole` Component から Sense で書く）。

- `distCoefficient` … `ScoreByDistance`（得意間合い）の広がり  
- `farnessCoefficient` … 様子見用 `farness` の広がり  
- `hitCoefficient` … `ScoreByHitCount`  
- `stanceCoefficient` … `ScoreByStance`（`>1`）  

得意間合い `mid` は技データ（当面 `attackDatas[0]` の中点など）。係数とはフィールドを分けるが、更新タイミングは揃える。

近接固執（0〜1）の専用補正は使わない。性格差は係数の調整で出す。

## Action（手段候補）

Stance 配下で選ぶ候補（初期）: 接近、離間、隙作り近接、技0、技1、待機。

| Stance（目標） | 上げやすい手段 | 下げやすい手段 |
| --- | --- | --- |
| 不利脱出 | 隙作り近接、条件付き離間 | 無条件の連続離間 |
| 有利維持活用 | 有利距離の微調整、得意技 | 無闇な突っ込み／大後退 |
| ニュートラル様子見 | 待機、技切替、小移動 | 同一技連打、一方的な詰め切り |

## Evidence と更新ポイント

Stance の更新は経過時間だけにしない。**証拠 → ポイント加算 → 閾値超で Stance 再評価**。

| 証拠 | 意味 |
| --- | --- |
| 技の命中／空振り | その AttackIndex |
| 同一技の連続 | sameAttackStreak |
| 位置関係の大きな変化 | 再評価候補 |

入れない（初期）: ガード／ジャンプ対策の大加点。

更新後はポイントと、必要なら Evidence をリセット／減衰。Stance 変更時は `stanceContinueCount` を 0 に。

## テンポ・リセット行動メモ（軽い案・変更前提）

位置関係の呼び方はプレイヤー視点。敵の得意間合い＝**敵有利位置**、その外で殴る＝**敵不利位置**、様子見＝ニュートラル寄り。

### 移動力の前提

- 移動の強さはおおむね **リセット行動 > ユーザー移動 > 敵の通常移動**
- リセットさえ止められれば、ユーザーがテンポを取りやすい
- 敵有利位置での詰めなども、ユーザー移動よりわずかに弱い程度を想定
- 敵有利に入っても **即死ではない**

### 局面の型（ターンの感じ）

| 局面 | 感じ |
| --- | --- |
| 様子見 | 比較的ユーザーが自由に動ける |
| 敵不利位置での戦闘 | 行動権は五分五分で殴り合い |
| 敵有利位置での戦闘 | 一方的に殴られ、隙を見て逃げる必要がある |

### リセット行動の置き方（ハイリスクハイリターン案）

様子見／敵不利位置では、リセットを **ハイリスクハイリターンな攻撃** として置く。止められればかなりテンポを取れる。

| 局面 | リセットの位置づけ（案） |
| --- | --- |
| 敵不利位置での戦闘 | 通常はローリスク・ミドルリターン以上が来る。そこを対処できれば勝てるので **最も警戒すべき行動** にリセットを置く |
| 様子見 | 出させて対処すれば確実に有利、失敗すれば確実に不利。**誘発すべきか頭を悩ませる選択肢** |
| 敵有利位置 | 必須ではないが、ハイリスクハイリターンとして置いてもよい。ミドルリスク・ローリターンが多い中で、一気に有利間合いを作る賭けになる。避けながら距離を取るか、リスクを取って強いリセットを待つかの駆け引き。上手くなるほど不利位置ではリセットのリスクを負う工夫、有利位置ではリセットのリスクを減らす工夫、になりうる。ただし「距離を変える」リターンだけでリスク差が薄いなら、やるならもう少しきれいにまとめたい。**コンセプト／フロー上、ここに駆け引きを置くかは一考** |

別案: リセットを **敵の位置調整専用** にする場合、近距離（敵有利）ではあまり使わない想定。不利位置は「強いので逃げる間合い」としてシンプルになる。

### 妥協択（余談・欲しい案）

リセット攻撃に対し、やれば成功はするが **美味しさは4割程度** の微不利で妥協できる選択肢を用意したい。
