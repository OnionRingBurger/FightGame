## P0: メインの遊び（敵込みの間合い格闘）

敵が攻撃し、プレイヤーが読み・対抗でき、こちらも技を使い分けて戦える状態にする。これがないと部屋で操作確認するだけになる。

### 敵が「問題」を出す

- [ ] **敵攻撃の予兆表示**（最初透明 → 攻撃開始に近づくと色が付く。docs 敵節）
- [x] **敵の技選択**（近／遠など。Chase の「0番固定」をやめ、間合いで index を選ぶ）
- [ ] **BT を戦える最低限まで**（必要な Cond／Action だけ具体化。総合判断の厚みは遊びが立ってからで可）

### プレイヤーが「答える」（段階実装）

コアが「有利間合いを探して維持する」になった以上、ガード／ジャンプの最終形（攻撃種×対抗の有効度マトリクス、間合いごとの得意不得意）は今はやらない。複雑すぎて実装しきれないリスクが高い。距離による近／遠の使い分けも、コア維持の前ではメインにしない。

段階:

1. **耐久手段としてだけ**（被弾を防ぐ／避ける。疲弊や失敗ペナルティは最小）
2. **アクション後メリットで役割差**（成功すると攻撃が強くなる等。既存案の「決めると強化→より良い位置で戦いたい」はコアと矛盾しない）
3. **可能なら間合い要素を織る**（成功帯が間合いに触れる、種ごとの有効度など。余裕があれば）

- [x] **段階1（ガード）**: 敵攻撃に対する耐久手段として通す（`GuardAction` で被ダメ軽減）
- [x] **段階1（ジャンプ）**: 回避手段として通す（物理ジャンプで判定を外す。ガードのような専用軽減は無しで可）
- [ ] **段階2**: 成功時の強化など、役割差のためのメリット
- [ ] **段階3（任意）**: 成功帯・間合いとの絡み（やりすぎて動きが固定化しないよう注意）
